# C파트 1주차 개념 정리

범위: Regex·Match·Span 개념, 이름·전화번호·이메일의 가상 예시, 공통 출력 형식 후보 정리.

## Regex 핵심 개념
| 개념 | 표기 | 해석 |
|---|---|---|
| 문자 클래스 | `[0-9]` | ASCII 숫자 한 글자 |
| 반복 | `{4}`, `+`, `?` | 정확히 4회, 1회 이상, 0~1회 |
| 선택 | `cat|dog` | 두 후보 중 하나 |
| 그룹 | `(ab)+` | ab를 묶어 반복하고 캡처 |
| 비캡처 그룹 | `(?:ab)+` | 묶어서 반복하되 캡처하지 않음 |
| 리터럴 | `\.` | 임의 문자가 아닌 마침표 자체 |

`r"..."`는 Python raw string 표기다. Regex의 역슬래시를 Python 문자열 이스케이프와 구분해서 쓰기 편하다. `[0-9]`는 ASCII 숫자로 범위를 명시한다.

`search`는 문자열 안의 첫 일치, `fullmatch`는 전체 문자열의 일치 여부를 확인한다. `finditer`는 원문에서 겹치지 않는 Match를 왼쪽부터 순회한다. `group()`은 일치 문자열, `span()`은 `(start, end)`를 반환한다.

## Span 정의와 예제
원문 `메일: a@example.com`에서 `a@example.com`은 `[4, 17)`이다. 시작은 포함하고 끝은 제외한다. `원문[4:17] == "a@example.com"`이며 길이는 `17-4=13`이다.
Python str의 문자 좌표를 사용한다. 한국어·이모지가 포함되어도 UTF-8 바이트 수로 위치를 계산하지 않는다. 한 화면 글자가 여러 코드 포인트일 수도 있으므로 화면 글자 수와도 구별한다.


## 세 요소의 가상 예시 기준
- 이름: 김하늘, 이다온, 남궁하린, Alex Morgan. 예시에서 조사·호칭은 제외하고 영문 이름 내부 공백은 포함한다.
- 전화번호: 010-0000-0000 같은 합성 문자열. 기본 패턴의 구조를 설명할 때 `010-[0-9]{4}-[0-9]{4}`를 사용할 수 있다.
- 이메일: a@example.com, haneul@example.com 등 합성 예시.
- 세 요소 모두 원문상의 시작·끝 위치와 label을 기록한다. 이름을 Regex로 탐지했다는 뜻은 아니다.

지원할 모든 전화번호·이메일 형식, 경계 규칙, NER 연동 및 병합 정책은 이번 문서에서 확정하지 않는다.

## JSON 표현
Span은 정보이고 JSON은 전달 문법이다. 후보 A는 start/end 필드, B는 span 객체, C는 span 배열로 표현한다. 아래에 각 후보를 직접 제시한다. 이 파일의 JSONL 예시는 작성 편의를 위해 A를 사용했으며, 팀 공통 출력 형식을 확정한 것은 아니다.

기술 참고: https://docs.python.org/3/library/re.html

## 공통 Span JSON 형식 후보
원문 `이름: 김하늘`에서 이름의 구간은 [4, 7)이다.

A. 평면 필드: 접근이 단순하고 위치의 의미가 명확하다.
```json
{"start":4,"end":7,"label":"NAME","text":"김하늘"}
```
B. span 객체: 위치를 한 묶음으로 표현하되 접근 단계가 늘어난다.
```json
{"span":{"start":4,"end":7},"label":"NAME","text":"김하늘"}
```
C. span 배열: 간결하지만 [시작, 끝] 순서 규약이 필요하다.
```json
{"span":[4,7],"label":"NAME","text":"김하늘"}
```
label 이름, text 필드의 필수 여부, source 같은 추가 필드, 원문을 포함한 응답 구조는 팀 협의 대상이다. 정답 주석에는 모델 점수나 탐지 출처를 임의로 붙이지 않는다.

## fixtures_regex.jsonl 구성
JSONL은 한 줄마다 독립된 JSON 객체 하나를 저장한다. 테스트를 실행해 생성한 결과 로그가 아니라, 향후 테스트에 사용할 입력과 기대 구간을 정리한 fixture다.

| 필드 | 의미 |
|---|---|
| id | 예시 식별자 |
| text | 수정하지 않은 입력 원문 |
| expected | 수동 작성한 기대 Span 목록 |
| note | 예시의 의도와 주석 기준 |

expected 안의 각 항목은 start, end, label, text를 가진다. NAME·PHONE·EMAIL의 세 label을 제안한다. 개인정보가 없는 문장은 빈 배열로 기록한다. 동일한 이름이 반복되면 서로 다른 위치를 별개 항목으로 기록한다. JSONL 안의 `\n`은 JSON을 읽은 뒤 실제 줄바꿈 한 글자가 된다.

파일 이름은 로드맵의 `tests/fixtures_regex.jsonl`을 유지했다. 사용자 요청에 따라 NAME도 포함한 세 요소 예시를 담았다. 이름까지 Regex가 탐지해야 한다는 뜻은 아니다. 추후 Regex만 평가한다면 PHONE·EMAIL 기대 항목을 대상으로 하고, NAME 기대 항목은 NER 또는 통합 탐지 평가에서 사용하도록 팀과 합의한다.

## 포함한 가상 사례
18개 사례: 세 요소 혼합, 각 요소 단독, 호칭, 복성, 두 글자 이름, 영문 이름, 이름 반복, 두 사람의 정보, 줄바꿈, 이모지, 문장부호, 일반명사, 기관·장소, 일반 숫자, 빈 문자열, 일부 요소만 등장하는 문장.

예시의 이름·번호·주소는 합성 자료이며 실제 연락처의 존재를 확인한 것이 아니다. 모델 예측, 사례 실행 결과, 성능 수치는 포함하지 않는다.
