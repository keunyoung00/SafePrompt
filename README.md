# 🛡️ SafePrompt

### LLM 입력 전 개인정보 자동 탐지 및 선택적 마스킹 서비스

SafePrompt는 사용자가 ChatGPT와 같은 LLM 서비스에 텍스트를 입력하기 전에 개인정보를 자동으로 탐지하고, 사용자가 선택한 정보를 마스킹하여 개인정보 노출 위험을 줄이는 프로젝트입니다.

Transformer 기반 개체명 인식(NER)과 정규표현식(Regex)을 결합하여 개인정보를 탐지하고, Streamlit 기반 웹 인터페이스에서 마스킹할 항목을 직접 확인하고 선택할 수 있도록 구현하는 것을 목표로 합니다.

## 1. 프로젝트 개요

LLM을 활용하는 과정에서 이름, 전화번호, 이메일 등의 개인정보가 포함된 텍스트를 그대로 외부 서비스에 전달할 수 있습니다.

SafePrompt는 이러한 위험을 줄이기 위해 LLM에 입력하기 전 개인정보를 탐지하고 마스킹하는 과정을 제공합니다.

**주요 목표**

- 텍스트에 포함된 개인정보 자동 탐지
- NER와 Regex를 결합한 Hybrid 탐지
- 사용자가 직접 확인하고 선택하는 개인정보 마스킹
- 원본 개인정보를 외부 LLM에 전달하지 않는 처리 구조
- 탐지 성능 비교 및 개인정보 보호 기능 검증

## 2. 주요 기능

| 기능 | 설명 |
|---|---|
| 개인정보 탐지 | Transformer NER를 활용한 문맥 기반 탐지 |
| 패턴 기반 탐지 | Regex를 활용한 전화번호 및 이메일 탐지 |
| Hybrid 탐지 | NER와 Regex 결과를 결합하고 중복·충돌 처리 |
| 선택적 마스킹 | 사용자가 탐지된 개인정보 중 마스킹할 항목 선택 |
| LLM 연동 | 마스킹된 텍스트만 외부 LLM에 전달 |
| 웹 인터페이스 | Streamlit 기반 입력·검토·결과 확인 화면 |

**1차 지원 대상:** `PERSON`, `PHONE`, `EMAIL`

LLM 응답 후 로컬 개인정보 복원 기능은 필수 구현 범위에서 제외하고, 개발 진행 상황에 따라 추가하는 선택 기능으로 계획하고 있습니다.

## 3. 시스템 처리 흐름

1. **사용자 입력:** 개인정보가 포함될 수 있는 텍스트 입력
2. **개인정보 탐지:** NER와 Regex로 개인정보 후보 탐지
3. **탐지 결과 병합:** 중복 및 충돌 해결
4. **사용자 검토:** 탐지된 개인정보 확인 및 마스킹 항목 선택
5. **로컬 마스킹:** 선택된 개인정보를 Placeholder로 치환
6. **LLM 처리:** 마스킹된 텍스트만 외부 LLM에 전송
7. **결과 출력:** LLM 응답과 Placeholder 상태 확인

**마스킹 예시**

입력: `김민수의 전화번호는 010-1234-5678입니다.`

마스킹: `[PERSON_1]의 전화번호는 [PHONE_1]입니다.`

원본 개인정보와 Placeholder 대응표는 외부 LLM에 전송하지 않고 로컬에서 관리하는 것을 원칙으로 합니다.

## 4. 사용 기술 및 데이터셋

**개발 기술**

- Language: Python
- NLP: Transformer 기반 NER
- Framework: PyTorch, Hugging Face Transformers
- Pattern Detection: Regular Expressions
- Web UI: Streamlit
- LLM: 외부 LLM API 연동 예정
- Version Control: Git, GitHub

NER 기반 모델과 Tokenizer의 최종 구성은 팀 내 비교 및 검토를 거쳐 확정할 예정입니다.

**데이터셋**

[BCCard/privacy-filter-openpii-masking](https://huggingface.co/datasets/BCCard/privacy-filter-openpii-masking)

BC카드 공개 개인정보 탐지·마스킹 데이터셋을 활용합니다. 데이터 전처리 과정에서 개인정보 위치 정보와 Tokenizer 정렬을 검증하며, 모델 성능은 분리된 평가 데이터에서 측정할 계획입니다.

데이터셋의 라이선스 및 원 출처 표기 조건을 준수합니다.

각 담당자는 독립적인 모듈을 개발하고, 공통 입출력 형식을 기준으로 최종 시스템을 통합합니다.

## 7. GitHub 협업 방식

팀원별 개발 브랜치를 사용하고, Pull Request를 통해 공통 브랜치에 변경사항을 반영합니다.

| 브랜치 | 용도 |
|---|---|
| `main` | 공통 통합 코드 |
| `devA` | A 담당 개발 |
| `devB` | B 담당 개발 |
| `devC` | C 담당 개발 |
| `devD` | D 담당 개발 |

**작업 절차**

1. 담당 브랜치에서 코드 작성
2. 변경사항 Commit 및 Push
3. `main` 브랜치로 Pull Request 생성
4. 코드 검토 후 Merge

공통 파일이나 다른 담당자의 모듈을 변경해야 하는 경우 사전에 공유합니다.

## 9. 보안 및 유의사항

- 실제 개인정보 및 원본-Placeholder 대응표를 GitHub에 업로드하지 않습니다.
- API Key와 인증 정보는 환경변수 또는 비공개 Secrets로 관리합니다.
- 대용량 모델 파일은 별도의 공유 저장소에서 관리합니다.
- 외부 LLM 테스트에는 실제 개인정보 대신 가상 예제를 사용합니다.
- 개인정보 탐지 및 마스킹 결과가 완벽한 보호를 보장하지 않는다는 한계를 고려합니다.
